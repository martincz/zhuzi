## L1 · 澄清（Clarification）

### 触发信号

- 文档主体没有结构性错误，但某些句子让你需要读第二遍才能猜出意思
- 代词指代不清（"它"指谁？"这个"指哪个？）
- 限定语密度过高（"通常""一般""在某种程度上""大多数情况"——一段超过 3 个就可疑）
- 确定性级别错位（强结论用了"可能"；弱证据用了"肯定"）
- 句子结构头重脚轻或悬垂

### 常用动作词汇

- "你这句说'X'——谁是 subject？"
- "'通常'、'大多数情况'——具体是多高的比例？"
- "这一段'它'、'这个'出现了 5 次，每个指代不同的东西"
- "你说'可能'，但后面的决策是按'一定'执行的——这里有语气错位"

### 典型样本

**糟糕（需 L1）**：
> "系统在处理大量请求时，通常会采取相应策略来保证稳定性。"

**费曼式追问**：
- "系统"——哪个组件？
- "大量请求"——多大？QPS > 什么值？
- "通常"——总是还是有条件？
- "相应策略"——具体做什么动作？
- "稳定性"——按什么指标衡量？不稳定时会发生什么？

**L1 修复后**：
> "当 X 服务接收到的 QPS 超过 Y 时，会触发 Z 降级策略：丢弃 W 类请求，保留 V 类请求。降级期间延迟上限从 A 放宽到 B。"

### 失败案例

- L1 应用到结构性问题：如果文档整个机制都没讲清楚，纠结单句语法是浪费。**这时应该切到 L2 或更深**
- 过度 L1 变成文字洁癖：不影响理解的表达差异不必强改

## L2 · 拆术语（De-jargon）

### 触发信号

- 一段话里专业词密度高到读起来像陌生语言
- 删掉专业词后，这段话变成空壳（没有剩余机制描述）
- 术语之间互相定义（"X 是指一种基于 Y 的 Z"，而 Y 和 Z 本身也是术语）
- 读者在术语堆前被挡住，没法进入实质讨论
- 作者用术语频率超过用具体动词 + 例子的频率

### 常用动作词汇

- "定义 X。你指的是 A 意义下的 X，还是 B 意义下的 X？"
- "'赋能'在这段出现了 3 次。把每一处改成这个词的真实指代——改不动就说明它本来是空的"
- "用六年级学生能听懂的话讲一遍。不许用任何术语"
- "输入 → 处理 → 输出。用这三个具体步骤重写"

### 典型样本

**糟糕（需 L2）**：
> "本方案采用模块化架构，实现业务能力的解耦与复用，通过中台化沉淀通用能力，赋能前台快速创新。"

**费曼式追问**：
- "模块化"——具体划分成哪些模块？边界是什么？
- "业务能力"——"能力"是一个什么东西？它可以被触摸、被调用、被测试吗？
- "解耦"——谁跟谁原来耦合？解耦后它们如何通信？
- "中台化沉淀"——这是一个动作还是一个状态？做了什么？
- "赋能前台"——前台得到了什么？没有"赋能"前它做不了什么？

**L2 修复后**：
> "本方案把代码按 A / B / C 三类功能拆成独立服务。原先 A 改动会引起 B 重新部署，拆分后 A 和 B 可以独立部署。A 功能被抽取为一个独立的 REST 服务，业务线 X 和 Y 都可以调用，不再各自维护一份。"

### L2 的核心技巧：动词化

**名词化的术语 → 还原为动词**：

| 术语（名词化）| 还原的动词 |
|--------------|-----------|
| 赋能 | 帮助 X 做 Y |
| 对齐 | 确认 X 和 Y 匹配 |
| 协同 | X 和 Y 共同完成 Z |
| 沉淀 | 把 X 写进可复用的模块 |
| 抓手 | 用 X 作为切入点做 Y |
| 闭环 | X 到 Y 到 Z 再回到 X |
| 生态 | X、Y、Z 围绕 W 互相依赖 |

**规则**：每次用到上面左列的词时，先问自己能不能用右列还原。还原不出来，这个词在你的语境下是空的。

### 失败案例

- L2 应用到真正的专业术语：有些术语确实有精确含义，硬拆会失真（比如"傅里叶变换"不能拆成"某种数学操作"）
- 区分"必要术语"（有精确定义、替代会失真）和"装饰术语"（可以用日常语言还原）

## L3 · 抓 Cargo Cult（Anti-ritual）

### 触发信号

- 形式完美但读完"不知道它实际做什么事"
- 流程 / 格式 / 模板 / 术语堆齐全，但看不到每一条对应的真实约束或真实效果
- 当你问"这个步骤为了防止什么具体问题"，对方答不上或用更高阶的术语回应
- 删掉这个流程的某一步，没人能说出会失去什么具体保护
- 作者优化的是"看起来专业 / 规范 / 严谨"，而不是"真的有效"

### 常用动作词汇

- "飞机不会降落。" （直接引用 cargo cult 的原始比喻，拒绝委婉）
- "去掉所有外在形式，核心目的达成了吗？"
- "把这一步删掉一天，**具体**会变差在哪里？"
- "这套流程是为了防御哪类真实事故？举出一个历史案例"
- "你有格式，没有精神。"

### 典型样本

**糟糕（需 L3）**：

代码评审 checklist：
> 1. 代码符合规范
> 2. 通过 lint
> 3. 有单元测试
> 4. 命名清晰
> 5. 经过两人评审
> 6. 补全文档

**费曼式追问**：
- "符合规范"——哪条规范？规范本身对应防御什么风险？
- "通过 lint"——lint 规则在保护什么？有没有被 lint 误判放过的 bug 案例？
- "有单元测试"——测试覆盖率？测什么层级？测试是真的在测行为还是只在测实现？
- "两人评审"——评审者有没有实际理解改动的上下文？他们点 approve 的标准是什么？
- "补全文档"——文档是给谁看？那个人真的会看吗？

**L3 诊断**：如果上述问题大部分答不上来，这套 checklist 是 cargo cult review——形式齐全，不防御任何真实失败模式。

**L3 修复方向**（不是给新 checklist，而是换一个角度）：
> 列出过去 12 个月发生的事故；每条事故写出它**不被哪个 check 覆盖**；基于"覆盖实际事故"重建 checklist，删除无事故对应的步骤。

### L3 的社交代价

- L3 往往伤感情。指出"你做的事是 cargo cult"等于说"你的努力没价值"，即使这不是讲者的本意
- 费曼本人在挑战者号调查中付出了社交代价——Rogers 称他"a real pain in the ass"
- 这个代价是 L3 的固有成本，不是可以规避的副作用。**如果你不愿意承担这个代价，就不要进入 L3**——停在 L1/L2 是诚实的选择
- 使用 L3 前问自己：指出这个 cargo cult，**真的会让事情变好吗**？如果对方没有权力 / 意愿 / 能量去改，这可能只是让你看起来清醒——那是 cargo cult 的镜像

### 费曼的经典 L3 执行案例

**巴西物理教育批评（1963）**：
费曼在里约第一届美洲物理教育会议上当众宣称"巴西根本没在教科学"——学生能背公式但换问法就不会；教科书里的"实验数据"是编造的。这是最纯粹的 L3——指认整个教育系统是 cargo cult。

**挑战者号附录 F（1986）**：
"For a successful technology, reality must take precedence over public relations, for nature cannot be fooled." —— 这不是委婉批评，是直接判定 NASA 管理层的安全声明是 cargo cult science。

### 失败案例

- L3 应用过早：没先用 L2 拆术语就直接指控 cargo cult——批评不够扎实，容易被反驳为"你没理解我的专业术语"
- L3 应用过狠：把所有不完美的流程都贴 cargo cult 标签——很多流程是真的有效只是效果需要长期观察
- 用 L3 当情绪出口：因为讨厌对方的风格就贴 cargo cult 标签——这是用费曼的武器做自己的偏见

## L4 · 演示式重写（Demonstrative Rewrite）

### 触发信号

- 用文字已经说不清的时候
- 需要让对方"无法再忽视"某个关键特征
- 复杂机制用叙述会让人在错的地方分心，用演示能直接锚定正确焦点
- 问题的严重程度需要一个物证，否则讨论会一直绕
- 对方每次都用新的抽象术语回应你的拆解——需要一个具体的东西打破循环

### 常用动作词汇

- "与其写三段解释，给我一个 X 的测试输出"
- "能不能做一个 10 秒的演示，替代这 100 页报告？"
- "输入这个 → 输出这个。看到差距了吗？"
- "画一张图，把 X 和 Y 的区别放在同一坐标系上"

### 费曼的终极 L4 案例

**O 型环冰水实验（1986 Rogers Commission 电视直播）**：

背景：挑战者号调查陷入僵局。NASA 管理层用厚达数百页的报告辩解"安全系数 3"；工程师的警告被技术术语包裹。

费曼的动作：在电视直播听证会上把一块 O 型环橡胶放进一杯冰水，用钳子夹住展示它失去弹性。**30 秒**——替代了数百页报告没能完成的论证。

为什么这是纯 L4：
1. 把复杂工程问题还原为每个人都能看懂的物理现象
2. 绕过所有官僚语言保护层
3. 观众（包括非专家）可以直接验证结论
4. 证据从"你信不信作者"变成"你信不信自己的眼睛"

### L4 的不同形式

不是所有 L4 都需要物理演示。根据上下文选择：

| 形式 | 适用场景 | 例子 |
|------|---------|------|
| **物理演示** | 机制可观察 | O 型环冰水、盐和水的沉降实验 |
| **测试输出** | 软件 / API 契约 | "调用 X 两次、十次、一千次后的系统状态日志" |
| **输入 / 输出样本** | 数据转换、算法 | "给定输入 A，输出 B；给定输入 A'，输出 C" |
| **脑中画面** | 抽象概念 | 费曼解释光波：一只苍蝇漂在泳池里上下颠簸 |
| **对比图** | 两种方案差异 | 同一数据在两种模型下的预测 vs 真实值 |
| **失败案例重现** | 流程有效性论证 | "重演一次事故：按现在流程能不能拦住？" |

### L4 的成本

- 工作量最大——需要真的搭实验、做测试、画图、写代码
- 做不好的 L4 适得其反：一个糟糕的类比（见反模式 #9 作弊简化）会让读者对新场景推断错误
- **L4 的类比必须标出失效边界**：费曼在解释量子力学时说"It's a little bit like X—but the analogy breaks down at Y"——类比 + 边界声明，是 L4 的标配

### 失败案例

- 用 L4 炫技：因为能做演示就做演示，但演示没有真正回应原问题
- 类比作弊：用一个同样不理解的东西去"演示"（见反模式 #3 定义递归、反模式 #9 作弊简化）
- 拒绝 L4 但实际需要：某些概念（比如量子力学、复杂系统涌现）确实需要演示才能讲清楚，硬用文字会让所有读者误读

## 切换规则

### 正常进入路径

默认从 **L1 开始**，发现问题更深就逐步下切：

```
L1 澄清（语义 / 指代） → 不够 → L2 拆术语（名词墙 / 定义递归） → 不够 → L3 抓 cargo cult（形式无实质） → 不够 → L4 演示式重写（需要物证）
```

### 不可跳档

- L1 → L3：没先拆术语就指控 cargo cult，批评不够扎实。对方可以反驳"你没理解我的术语"
- L2 → L4：没指认 cargo cult 就开始做演示，演示可能解决了错的问题

### 可以跳档的场景

- **用户明确要求深档**："这是不是 cargo cult？" → 直接 L3
- **问题显然是深档**：文档整体就是 cargo cult 样本，没有可澄清的句子 → 直接 L3
- **用户粘了代码 / 数据 / 样本**：已经有 L4 原料 → 直接 L4 分析

### 退出规则

任何档位发现**对方其实理解但表达失败**，退回 L1：
- 一个资深工程师可能用了糟糕的术语，但他脑子里的机制是清晰的
- 这时 L3 会误伤——应该回到 L1 帮他把脑子里的东西讲出来

### 档位 × 场景对照

| 场景 | 推荐起点 |
|------|---------|
| 代码评论 / code review | L2（拆术语）|
| API spec / 接口文档 | L1（澄清）|
| 架构方案评审 | L2 → L3（拆术语后查 cargo cult）|
| 内部流程 / checklist 评审 | L3（直接查 cargo cult）|
| 面向用户的说明文档 | L1 → L4（清晰 + 必要时加演示）|
| 科研论文 / 技术白皮书 | L2（术语密度高）|
| 挑战者号级别的制度性自欺 | L3 → L4（指认 + 演示）|
| 量化研究报告 / backtest 说明 | L2 → L3（术语 + 可验证性检查；复杂时切 López 视角）|

## 档位 × 心智模型对应

每一档主要激活哪些心智模型（见 [方法论](methodology.md)）：

| 档位 | 主要模型 | 辅助模型 |
|------|---------|---------|
| L1 | 不确定性是力量（确定性错位）| 命名不等于理解（指代不清）|
| L2 | 命名不等于理解 | 具象化思考 |
| L3 | 反自欺 | 自然不可被愚弄、命名不等于理解 |
| L4 | 自然不可被愚弄、具象化思考 | 拒绝虚假简化（类比必须有边界）|

## 档位检查清单（使用前自查）

1. **我是在哪一档**？不清楚就停下来分类
2. **我有没有跳档**？L1 → L3 是常见错误
3. **我愿不愿意承担这一档的代价**？L3 有社交代价，L4 有工作量代价
4. **我是在解决对方的问题，还是在证明自己清醒**？后者是 L3/L4 的 cargo cult 镜像
5. **用完后，问题真的变清楚了吗**？如果对方更糊涂，档位选错了
