# Don Norman · UI 评审 Checklist

> 本文件是 `don-norman-perspective` 的可操作 UI / UX 评审 checklist，把 [SKILL.md](../SKILL.md) 的认知诊断框架展开为**逐项可勾选的检查清单**。
>
> 适用场景：design review、可用性评估、新员工 onboarding 反馈、改版前现状评估。
>
> **使用方式**：把待评审的 UI（截图 / mockup / 真实产品）拿出来，逐节按 checklist 走。每一项给 PASS / PARTIAL / FAIL 评级 + 具体证据 + 修复方向。

---

## Section 0: 评审前的准备

在开始按 checklist 之前，先确定：

- [ ] **被评审对象是什么**？（一个具体页面 / 整个 app / 一个流程）
- [ ] **核心用户是谁**？（年龄、设备、专业程度、使用频率）
- [ ] **核心任务是什么**？（用户最需要完成的 1-3 件事）
- [ ] **测试方法**：扔给从没用过的人 + 给老用户访谈 + 自己上手
- [ ] **评审时长预算**：每个 section 15-30 分钟

---

## Section 1: Discoverability 检查（可发现性）

### 1.1 第一屏 / 第一印象

- [ ] 用户登录 / 第一次打开后 30 秒内，**能不能找到核心任务的入口**？
- [ ] 第一屏是否被**装饰性元素占满**（大 logo、宣传图、空白）？核心任务是否被挤到第二屏？
- [ ] 主任务按钮的**视觉权重是否最高**（最大、最亮、最突出）？
- [ ] 第一屏是否有**任何 hidden gestures**（用户必须长按 / 滑动 / 双击才能发现的功能）？

### 1.2 主导航

- [ ] 主导航**所有项是否可见**（不藏在 hamburger menu 里）？
- [ ] 当前位置是否**在导航中明确高亮**？
- [ ] 用户在某个深层页面，能不能**3 秒内回到主页**？
- [ ] 面包屑（breadcrumb）是否需要？需要的话有没有？

### 1.3 功能可发现

- [ ] 高频功能是否**在显眼位置**（不藏在 settings / advanced / labs）？
- [ ] 新功能上线后是否**有 onboarding 提示**？提示是否会被忽略（例如蓝点太小）？
- [ ] 文档 / 帮助按钮是否**位置一致**？
- [ ] 关键操作是否**只有一个入口**还是**多个等效入口**？（多个入口提高可发现性）

### 1.4 测试

- [ ] **5 秒测试**：给新用户看 5 秒截图，问"这是做什么的？"——能答对吗？
- [ ] **30 秒测试**：让新用户在没有引导的情况下找到核心任务——能找到吗？
- [ ] **手势探索**：让新用户摸索 1 分钟，能不能发现长按 / 双击等隐性功能？

### 评级

- ✅ **PASS**：5 秒测试和 30 秒测试都通过；hidden gestures < 2 个且都有可见替代
- ⚠️ **PARTIAL**：30 秒测试通过但 5 秒测试失败；或 hidden gestures >= 2 但有 onboarding 提示
- ❌ **FAIL**：30 秒测试失败；核心功能藏在多层菜单或 hidden gesture 里

## Section 2: Feedback 检查（反馈）

### 2.1 即时反馈（< 100ms）

- [ ] 每个**点击 / 触摸**都有视觉反馈（按下态、高亮、涟漪效果）？
- [ ] 表单字段获得焦点时有**视觉变化**（边框、底色）？
- [ ] 拖动 / 长按等手势在**触发瞬间有反馈**（不是动作完成后）？

### 2.2 进度反馈（100ms - 10s）

- [ ] 100ms - 1s 的延迟有 **spinner / loading indicator**？
- [ ] 1s - 10s 的延迟有 **progress bar 或文字进度**？
- [ ] > 10s 的延迟有 **预计时间** 显示？
- [ ] 长时间操作可以 **取消** 吗？取消反馈即时吗？

### 2.3 完成反馈

- [ ] 操作完成后用户**立即知道完成了**（toast / 跳转 / 视觉变化）？
- [ ] 完成反馈是否 **specific**（"已保存 X 文件" 而不是 "Saved"）？
- [ ] 完成后是否告诉用户 **下一步可以做什么**？

### 2.4 错误反馈

- [ ] 错误信息是否 **specific**（"密码缺少特殊字符" 而不是 "无效密码"）？
- [ ] 错误信息是否 **告诉用户怎么修**？
- [ ] 错误是否 **inline 显示**（在出错的字段旁边）而不是在表单底部 / 提交后？
- [ ] 是否有 **"Error 4032" / "Something went wrong" / "Unknown error"** 这种垃圾错误信息？

### 2.5 状态反馈

- [ ] 当前 mode / 状态 / 选择是否**始终可见**（status bar、title、高亮）？
- [ ] 自动保存状态是否**用户可见**（"已保存" / "未保存" / "正在保存"）？
- [ ] 网络状态是否**用户可见**（offline 时有提示）？
- [ ] 用户中断 5 分钟回来，能不能**立刻判断当前状态**？

### 评级

- ✅ **PASS**：所有动作 100ms 内有反馈；progress / 完成 / 错误信息都 specific
- ⚠️ **PARTIAL**：部分操作反馈延迟或非 specific；错误信息有 1-2 处垃圾文案
- ❌ **FAIL**：长时间操作无 progress；错误信息全是 "Something went wrong"；状态对用户不可见

## Section 3: Conceptual Model 检查（概念模型）

### 3.1 设计师 Model 与 System Image 一致性

- [ ] 设计师**口头讲述**这个产品的工作原理 → 这个原理在 UI 上**直接可见**吗？
- [ ] 隐喻（icon、命名、布局）是否**对齐实际行为**？
- [ ] 有没有"icon 暗示 X 但实际是 Y"的不对齐情况（云朵 = 本地存储）？

### 3.2 用户 Model 与实际行为一致性

- [ ] 用户测试中**反复犯的 mistake** 是什么？这暗示用户 model 哪里错？
- [ ] 用户**反复问"这个是什么意思"**的地方在哪？
- [ ] 用户对系统**最常见的误解**是什么？

### 3.3 命名与文案

- [ ] 按钮命名是否**精确**（"删除" 是真删除还是隐藏？"分享" 是公开还是私密？）？
- [ ] 状态命名是否**清晰**（"已完成" 还是 "已处理"？"已发送" 还是 "已送达"？）？
- [ ] 是否有**误导性命名**（"私密分享" 实际是任何人有链接都能访问）？
- [ ] 文案是否**用用户语言**而不是工程语言（"同步" vs "提交到服务器"）？

### 3.4 不可逆操作

- [ ] **删除 / 发送 / 提交** 等不可逆操作是否有 **明确确认**？
- [ ] 是否有 **撤销窗口**（30s undo toast）？
- [ ] 重要数据删除是否需要 **typing 确认**（输入名字才能删）？
- [ ] 用户是否清楚 **"这个操作能不能撤销"**？

### 3.5 默认设置

- [ ] **默认设置**是否符合用户最保守预期（隐私 default = 最严格）？
- [ ] 默认值是否对用户**有利**还是**对公司有利**（dark patterns）？
- [ ] 用户能不能**轻易发现并修改**默认设置？

### 评级

- ✅ **PASS**：用户 model 和实际行为对齐；命名精确无误导；不可逆操作有保护
- ⚠️ **PARTIAL**：1-2 处命名误导或 model 不一致；默认设置中性
- ❌ **FAIL**：System Image 系统性骗用户；默认设置 dark patterns；无撤销机制

## Section 4: Affordance vs Signifier 检查

### 4.1 Signifier 充足性

- [ ] 每个**可点击元素**都有 signifier（按钮样式、链接颜色、icon）？
- [ ] **可拖动元素**有 signifier（grip handle、拖动 cursor、视觉提示）？
- [ ] **可滑动 / 可滚动区域**有 signifier（scrollbar、阴影提示更多内容）？
- [ ] **隐藏内容**（折叠 / 展开）有 signifier（箭头、"展开"按钮）？

### 4.2 Signifier 一致性

- [ ] 同一类元素（如所有按钮）**视觉一致**？
- [ ] **可点击 vs 不可点击** 视觉区分明显？
- [ ] **disabled 状态** 与 enabled 状态明显不同？

### 4.3 Signifier 准确性

- [ ] Signifier 暗示的功能**和实际功能一致**？
- [ ] 没有"看起来像按钮但其实是装饰"的元素？
- [ ] 没有"看起来像装饰但其实可点"的元素？

### 4.4 术语精确

- [ ] 团队内部讨论时，是否**正确使用 affordance vs signifier 术语**？
- [ ] 文档中是否**避免把 signifier 误称为 affordance**？

### 评级

- ✅ **PASS**：所有交互元素有充足 + 一致 + 准确的 signifier；术语正确
- ⚠️ **PARTIAL**：少数元素 signifier 不足或不一致；术语偶有混用
- ❌ **FAIL**：大量隐性手势；可点击 vs 不可点击视觉混淆；术语全用 affordance 不分

---

## Section 5: Slips vs Mistakes 检查

### 5.1 Slip 防护（动作走样）

- [ ] **危险按钮**（删除、发送、支付）和**安全按钮**（取消、保存）**视觉强分离**（颜色、位置、大小）？
- [ ] **关键操作**有 **forcing function**（确认对话框、typing 验证、二次点击）？
- [ ] **撤销** 是否随处可用？撤销窗口够长（>= 30s）？
- [ ] 表单的**自动保存**是否完善？

### 5.2 Mistake 防护（意图错误）

- [ ] 用户能不能**预览操作结果**（删除前看到要删什么、发送前看到收件人）？
- [ ] **复杂操作**有没有教学 / 解释（"这个操作会做什么"）？
- [ ] 错误的 mental model 是否**主动纠正**（tooltip、inline 解释）？

### 5.3 Forcing Functions

- [ ] **Interlock**：危险操作前必须满足前置条件（"必须勾选才能继续"）
- [ ] **Lock-in**：未保存时退出有警告
- [ ] **Lockout**：危险区域有物理阻止（"删除"按钮初始 disabled，输入名字才 enable）

### 5.4 错误恢复

- [ ] 用户犯错后能不能**轻松恢复**？
- [ ] 误删数据有 **trash / recycle bin** 吗？保留多久？
- [ ] 误发送消息能 **撤回** 吗？

### 评级

- ✅ **PASS**：危险操作有 forcing function；撤销随处可用；错误可恢复
- ⚠️ **PARTIAL**：部分危险操作无保护；撤销窗口太短
- ❌ **FAIL**：删除无确认 + 无撤销；误操作无法恢复

## Section 6: Knowledge in the World 检查

### 6.1 状态可见

- [ ] 当前 mode / 状态在 UI 上**始终可见**？
- [ ] 用户中断 5 分钟回来，**不需要重新建立上下文**？
- [ ] 多步流程中，**前面填的内容在后面可见 / 可编辑**？

### 6.2 Inline 提示

- [ ] 表单字段有 **placeholder / 示例值**？
- [ ] 复杂字段有 **inline 帮助**（不是 tooltip 而是直接文字提示）？
- [ ] 错误信息 **inline 显示**（在出错字段旁边）？

### 6.3 自动保存

- [ ] 用户输入内容是否**自动保存草稿**？
- [ ] 保存状态**用户可见**（"已保存" 标记）？
- [ ] 关闭浏览器后回来，能不能**接着上次操作**？

### 6.4 减少记忆要求

- [ ] 是否要求用户记住超过 **7 个**东西（步骤、选项、规则）？
- [ ] **快捷键**有没有 inline 提示（hover 时显示）？
- [ ] **历史记录**是否可访问（最近文件、最近搜索、最近联系人）？

### 评级

- ✅ **PASS**：状态全部可见；inline 提示充足；自动保存完善
- ⚠️ **PARTIAL**：部分状态隐藏；少量信息要求记忆
- ❌ **FAIL**：用户必须记住多步流程的中间状态；无自动保存；中断后丢失数据

## Section 7: 可访问性（Accessibility）检查

> 这一节是 [反模式 N8](anti-patterns.md)（对老人 / 视障 / 新手敌对）的具体化。Norman 87 岁开 jam jar 要拿扳手——可访问性失败 = 设计在歧视。

### 7.1 视觉

- [ ] 文字对比度 ≥ **4.5:1**（WCAG AA）？关键文字 ≥ **7:1**（AAA）？
- [ ] 字体最小 **16px**（移动端）/ **14px**（桌面端）？
- [ ] 字重最低 **regular**（不是 light / ultra light）？
- [ ] **颜色不是唯一信号**（红绿色盲可读）？

### 7.2 触摸 / 交互

- [ ] 触摸目标 ≥ **44×44pt**（iOS）/ **48×48dp**（Android）？
- [ ] 触摸目标之间有 **足够间距**（防止误触）？
- [ ] 关键操作有 **可见 button 替代**（不强制手势）？

### 7.3 键盘可访问性

- [ ] 所有功能可以**纯键盘操作**？
- [ ] **tab 顺序**合理？
- [ ] **focus 状态**视觉清晰？

### 7.4 屏幕阅读器

- [ ] 所有 icon 有 **aria-label** / **alt text**？
- [ ] 表单字段有 **label**（不只 placeholder）？
- [ ] 动态内容更新有 **live region** 通知？

### 7.5 老人友好

- [ ] **80 岁老人**能用吗？让真实的老年用户试一下
- [ ] **手抖**用户能用吗（减少需要精确操作的部分）？
- [ ] **认知负担**对新手友好吗？

### 评级

- ✅ **PASS**：通过 WCAG AA；触摸目标够大；老人测试通过
- ⚠️ **PARTIAL**：1-2 项不达标但非核心
- ❌ **FAIL**：字体过细 / 对比度过低 / 触摸目标过小；老人无法使用

## Section 8: 自动化 / AI 决策（如适用）

> 这一节针对有自动化、AI 推荐、智能默认值的产品。Norman *The Design of Future Things* (2007) 反复警告 evaluation 鸿沟。

### 8.1 透明度

- [ ] 自动决策是否**用户可见**（"基于你的历史推荐"）？
- [ ] 推荐 / 排序是否有 **解释入口**（"为什么看到这条"）？
- [ ] AI 行为是否 **可追溯**（用户能看到 AI 做了什么）？

### 8.2 用户控制

- [ ] 自动行为是否 **可关闭 / 可调整**？
- [ ] 用户能不能 **覆盖** 自动决策？
- [ ] 默认设置是否 **保守**（隐私 default = 最严格）？

### 8.3 失败处理

- [ ] 自动化失败时，用户是否**立即知道**？
- [ ] 接管时，用户是否**知道当前状态**（自动驾驶失败前的车速、车道）？
- [ ] 接管是否**有缓冲时间**？

### 8.4 AI 反馈

- [ ] AI 输出是否 **可纠正**（用户标记错误）？
- [ ] AI 是否 **承认不确定性**（"我不确定" vs "我猜")？
- [ ] AI 错误是否会**学习**（不是同样错误反复出现）？

### 评级

- ✅ **PASS**：自动决策透明可控；失败有缓冲；AI 可纠正
- ⚠️ **PARTIAL**：透明度不足或控制有限
- ❌ **FAIL**：黑箱决策；自动化失败 surprise；用户无法干预

## 评审报告模板

完成 8 个 section 评审后，按以下模板汇总：

```markdown
# UX Review Report: [产品名 / 页面名]

## 评审基本信息
- 评审日期：
- 评审对象：
- 核心用户：
- 核心任务：
- 评审方法：

## 评级总览

| Section | 评级 | 关键问题数 |
|---------|-----|----------|
| 1 Discoverability | ✅/⚠️/❌ | X |
| 2 Feedback | ✅/⚠️/❌ | X |
| 3 Conceptual Model | ✅/⚠️/❌ | X |
| 4 Affordance vs Signifier | ✅/⚠️/❌ | X |
| 5 Slips vs Mistakes | ✅/⚠️/❌ | X |
| 6 Knowledge in the World | ✅/⚠️/❌ | X |
| 7 可访问性 | ✅/⚠️/❌ | X |
| 8 自动化 / AI（如适用） | ✅/⚠️/❌ | X |

## P0 问题（必须改）

[FAIL 评级的具体问题]

## P1 问题（应该改）

[PARTIAL 评级的具体问题]

## P2 问题（可以改）

[PASS 但有改进空间的问题]

## 修复优先级建议

[按"影响人数 × 严重度 ÷ 修复成本"排序]
```

## 使用建议

- **完整评审**：8 个 section 全过，适合改版前的现状评估，需要 4-6 小时
- **快速评审**：只过 1 / 2 / 3（discoverability + feedback + conceptual model 三件套），适合 design review，需要 1-2 小时
- **针对性评审**：根据问题类型只过相关 section，需要 30-60 分钟

**checklist 不是替代思考**：每个 PASS/PARTIAL/FAIL 都需要**具体证据**和**修复方向**——纯打勾的 checklist 是 cargo cult。

**与其他 skill 配合**：
- 文档清晰度问题 → 切到 `feynman-explainer` 的 L1/L2
- 代码层面的 UI 问题 → 切到 `linus-torvalds-engineer`
- 商业模式 / dark patterns 的判断 → 切到 `munger-checklist`
- 注意力工程 / 用户黏性 → 切到 `donald-trump-perspective` 的注意力 lens
